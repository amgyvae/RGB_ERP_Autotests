# Контакты

Запуск из `C:\Users\Administrator\Desktop\RGB_Test`:

```powershell
py run_workflow_and_report.py contacts_test.py
```

Без видимого окна Chrome:

```powershell
py run_workflow_and_report.py contacts_test.py --headless
```

Только тест и локальный отчёт, без записи в Sheets и отправки Telegram:

```powershell
py contacts_test.py
```

Требуются существующие Selenium, webdriver-manager, requests, gspread и google-auth.
Авторизация использует RGB_LOGIN/RGB_PASSWORD из окружения либо буквальные
login_val/pass_val из соседнего gpr_test.py. Сам gpr_test.py не импортируется и не запускается.
Пароли не записываются в новый код или отчёт.

## Объём

25 проверок, ID чек-листа 177–201, строки 213–237. Все применимые проверки выполняются
в обоих представлениях. Только просмотр, поиск, фильтры, размер страницы 10/20/30/40
и переходы между страницами; никакие контакты не создаются и не изменяются.
Проверки содержимого используют текущую полную выборку вида «Лист» как исходный набор,
а не независимо прочитанную БД. Поэтому тест проверяет согласованность UI, но не может
доказать достоверность исходных данных относительно БД. В HTML нет стабильных ID:
используется совокупность общих полей; полностью одинаковые записи блокируют сверку.
Справочник должен оставаться неизменным во время прогона.

Поиск: ввод без Enter, подстрока, нечувствительность к регистру; телефон от 6 цифр,
в том числе без скобок и дефисов. Поведение пробелов по краям пока не утверждено и не
используется как обязательный критерий. После F5 проверяется согласованность текущих
контролов и результата, но не обязательное сохранение настроек.

## Отчётность

run_workflow_and_report.py проверяет полноту и идентификатор
JSON-отчёта и передаёт только выполненные проверки в существующий sheet_reporter.py.
Тот пишет статусы в колонку даты листа «Чек-лист», находя точное название внутри
диапазона 213–237. Если строки переместятся, обновить CONTACTS_ROW_RANGE в run_workflow_and_report.py.
SKIP не записывается как успех или ошибка; прежняя ячейка остаётся неизменной.
Поэтому текущие пропуски всегда нужно смотреть в локальном отчёте/сводке Telegram.

Telegram использует существующие tg_send/tg_photo и настройку TG_ENABLED.
Настройка не включается автоматически. При полном успехе — один короткий заголовок;
при ошибках — только проваленные проверки с причинами и скриншот текущего прогона.
Пропуски отдельно отмечаются, неполный прогон не объявляется успешным.
Длинные сообщения разделяются, диагностический текст экранируется для HTML.

Логи: contacts_log_*.txt. JSON и скриншоты: contacts_diagnostics/<run_id>/.
Код завершения: 0 — все 25 PASS, 1 — FAIL или SKIP, 2 — ошибка сбора/отправки в Sheets.
HTML-снимки не отправляются; Telegram получает только скриншот при включённой отправке.

## Проверка разработки

Локальные тесты проверяют парсер отчёта, пропуски, границу 5/6 цифр, экранирование,
разделение сообщений и запрет чужого скриншота. Статические HTML пользователя позволяют
проверить извлечение карточек и селекторы, но не заменяют прогон динамического портала.
